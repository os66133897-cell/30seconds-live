# 30초의 기억 – 우리 재단 사람을 찾아라!

천안시청소년재단 행사에서 최대 150명이 참여하는 실시간 퀴즈입니다. 참가자, 관리자, 대형 송출 화면이 한 서버에 연결됩니다. Node.js 24, SQLite, 브라우저 SSE를 사용합니다.

## Windows에서 실행

1. ZIP을 풀고 Node.js 24 LTS를 설치합니다. 탐색기에서 server.mjs 파일이 보이는 폴더를 열고 주소창에 powershell을 입력한 뒤 Enter를 누릅니다.
2. 아래 명령을 순서대로 실행합니다. 비밀번호는 12자 이상으로 설정합니다. npm.cmd ci는 설치 또는 업데이트 때 실행합니다.

       npm.cmd ci
       $env:ADMIN_PASSWORD = '여기에 행사 전용 비밀번호 입력'
       npm.cmd start

3. Quiz listening on 3000이 보이면 브라우저에서 아래 주소를 엽니다. 사용 중에는 PowerShell 창을 열어 둡니다. 종료하려면 Ctrl+C를 누릅니다.

| 화면 | 로컬 주소 | 배포 주소 |
|---|---|---|
| 참가 | http://localhost:3000/ | 서비스 주소 + / |
| 관리자 | http://localhost:3000/admin | 서비스 주소 + /admin |
| 송출 | http://localhost:3000/screen | 서비스 주소 + /screen |

macOS나 Linux에서는 npm ci 실행 후 export ADMIN_PASSWORD 명령으로 비밀번호를 설정하고 npm start를 실행합니다. 기존 로컬 DB를 계속 사용하려면 기존 실행 폴더에서 수정된 파일로 시작하고, DATA_DIR을 사용 중이면 같은 값을 지정합니다. SQLite에는 DB 스키마 마이그레이션이 없습니다. 서버를 종료한 뒤 기존 data 폴더를 다른 위치에 복사하거나, 서버 실행 중에는 관리자 화면에서 전체 JSON 백업을 내려받습니다.

## 직원 명단 등록

관리자 화면에서 **직원 명단**을 엽니다.

- **직원 추가**에서 이름과 시설을 입력합니다. 같은 시설에 이름이 같은 사람을 함께 등록할 때는 A, B처럼 서로 다른 구분자를 지정합니다. 이름·소속·구분자가 모두 일치하면 중복입니다. 참가 등록 때 같은 시설의 동명이인은 구분자까지 입력합니다.
- **붙여넣기 미리보기**에서는 한 줄에 한 직원씩 아래 예시처럼 입력합니다. 선택 사항으로 이름/소속/구분자/별칭1|별칭2 형태도 사용할 수 있습니다.

       직원1/사무국
       직원2/천안시청소년수련관
       직원3/태조산청소년수련관

- **직원 명단 엑셀 양식**을 내려받거나, 기존 XLSX·XLS 파일을 직접 선택합니다. 파일의 첫 번째 시트에 이름·성명·직원명 중 하나와 소속·현소속·시설명 중 하나의 머리글이 필요합니다. 선택적으로 구분자와 별칭 열을 넣습니다. 사번 등 다른 열은 무시합니다. 최대 파일 크기는 5MB, 엑셀 범위는 최대 4,000행·128열입니다.
- 천청수, 태조산, 복커, 성정, 상담복지, 학교밖은 정식 시설명으로 바뀝니다. 입력 앞뒤의 공백과 빈 행을 정리합니다. 오류에는 원본 행 번호와 이유가 표시됩니다. 미리보기를 검토한 다음 **목록에 추가** 또는 **정상 행만 추가**를 눌러야 저장됩니다.
- CSV는 이름,소속,구분자,별칭 순서 또는 인식 가능한 머리글을 사용할 수 있습니다. JSON은 직원 배열 또는 staff 배열을 가진 객체를 지원합니다. 직원 한 명은 {"name":"가상직원","facility":"사무국","tag":"A","aliases":["별칭"]} 형식입니다. CSV·JSON은 UTF-8, UTF-8 BOM, CP949, EUC-KR을 지원합니다. 자동 감지는 UTF-8을 먼저 시도하므로 필요한 경우 인코딩을 직접 선택합니다.
- 목록은 가나다순으로 표시됩니다. 이름 검색과 시설 필터를 함께 사용하거나, 체크박스로 몇 명을 골라 삭제할 수 있습니다. **명단 전체 삭제**와 **명단 백업**도 제공됩니다. 참가자가 등록된 뒤에는 참가·채점 기준을 보존하기 위해 명단 수정이 잠깁니다.
- 연습용 파일은 samples/staff-import-sample.xlsx 및 samples/demo-staff.csv입니다. 모두 가상 인물입니다.

## 문제 등록과 채점

1. 관리자 **문제 관리**에서 문제, 유형, 시간, 배점을 입력합니다. 기본값은 30초, 정답당 10점입니다.
2. 유형 A는 정답을 한 줄에 하나씩 입력합니다. 별칭은 대표 정답 | 별칭1 | 별칭2 형식으로 씁니다. **정답 엑셀·CSV·JSON 파일**로 정답 및 별칭을 추가할 수도 있습니다. 미리보기로 정답을 편집 목록에 추가한 뒤 **문제 저장**을 누릅니다.
3. 유형 B는 본인과 같은 시설의 직원을 제외합니다. 정답 후보가 여럿이면 이름 A, 이름(A) 또는 이름/시설로 구별합니다. 같은 시설에도 동일 이름이 여럿이면 이름 A/시설을 사용합니다. 유형 A에서 허용할 구분 표기는 정답과 별칭으로 등록합니다.
4. 문제 목록에서 위·아래 버튼으로 순서를 바꿉니다. **백업 및 결과**에서 문제 JSON을 내보내거나 기존 문제 전체를 새 JSON으로 교체할 수 있습니다. samples/demo-questions.json을 가져오면 가상 문제로 연습할 수 있습니다.
5. 참가자는 제한시간 안에 제출 버튼 또는 Enter로 여러 번 답할 수 있습니다. 서버가 공백과 유니코드를 정규화하고 같은 정답에는 한 번만 점수를 줍니다. 오답은 감점하지 않습니다.

## 행사 진행과 QR

1. 송출 PC에서 /screen을 열어 **전체화면**을 누릅니다. 대기 화면에 참가 주소 QR이 자동 생성됩니다. 로컬 LAN 테스트에서는 송출 화면도 http://서버PC의IPv4:3000/screen 주소로 열어야 QR에 스마트폰이 접속할 수 있는 주소가 들어갑니다. 스마트폰과 서버 PC는 서로 통신 가능한 네트워크에 있어야 합니다.
2. 관리자 **실시간 운영**에서 **참가자 모집 시작 → 참가자 모집 마감 → 게임 시작 → 라운드 시작** 순서로 진행합니다. PC와 휴대폰에서 같은 서버 주소를 사용합니다.
3. 진행 중 **일시정지**, **재개**, **강제 종료**를 할 수 있습니다. 종료 후 **다음 라운드 → 라운드 시작**을 누릅니다. 마지막에는 **최종 결과 발표**를 누르거나 **게임 종료**로 종료합니다.
4. 송출 순위와 시상 영역을 보이게 하려면 **송출 화면 순위 공개**를 켭니다. 공동 순위는 1, 1, 3 방식입니다. 같은 순위가 여러 명이면 전원이 해당 순위에 표시됩니다.
5. **백업 및 결과 → 결과 엑셀 다운로드**에서 최종 순위, 라운드별 결과, 시설별 참여 현황이 들어 있는 XLSX를 받습니다. **결과 CSV 다운로드**도 함께 제공됩니다. 가상 경기의 결과는 samples/results-sample.xlsx에서 확인합니다.

## 백업과 데이터 삭제

- **전체 백업 다운로드**는 명단·문제·정답·참가자·점수·서버 기준 종료 시각을 UTF-8 JSON으로 저장합니다. **전체 백업 복원**은 현재 기록을 그 파일의 상태로 교체합니다. 참가자가 원래 주소와 브라우저 쿠키를 유지하면 같은 세션을 복구할 수 있습니다.
- **전체 게임 초기화 → 참가자·점수 삭제**는 참가 기록을 지우고 명단과 문제를 보관합니다. **문제·명단까지 삭제**는 앱에 저장된 해당 자료도 지웁니다. 다운로드한 백업과 결과 파일은 관리자가 보관 또는 폐기합니다.
- 실제 직원 명단, 결과, 백업, SQLite 데이터 폴더, 환경변수 파일 및 비밀번호의 접근 권한을 관리합니다. GitHub에는 소스와 가상 샘플만 올립니다.

## GitHub 업로드 및 Render 배포

1. GitHub에서 비공개 저장소를 만들거나 사용 중인 저장소를 엽니다. 프로젝트 파일을 저장소 최상위에 올립니다. server.mjs, workbooks.mjs, qr.mjs, package.json, package-lock.json, render.yaml, .gitignore, public, samples, vendor가 포함되어야 합니다. data, node_modules, 실제 백업은 제외합니다.
2. 신규 서비스라면 Render **New → Blueprint**에서 GitHub 저장소를 연결합니다. ADMIN_PASSWORD를 입력하고 Starter 서비스와 /var/data에 마운트하는 1GB 영구 디스크가 표시되는지 확인합니다. **Live**가 되면 기존 표의 배포 주소로 접속합니다.
3. 기존 서비스를 수정할 때는 먼저 관리자 화면에서 전체 JSON 백업을 받습니다. **같은 Render 서비스 및 동일한 연결 저장소·브랜치**를 사용합니다. Settings에서 빌드 명령을 npm ci --omit=dev && node --check server.mjs, 시작 명령을 node server.mjs, 헬스 체크를 /health로 맞춥니다. 기존 ADMIN_PASSWORD와 DATA_DIR, 디스크 마운트는 그대로 사용합니다.
4. 기존 서비스에서 **Manual Deploy → Deploy latest commit**을 실행합니다. 사용하던 URL에서 로그인해 직원 수와 문제 수를 확인합니다. 무료 서비스에서 로컬 파일이 유실되면 백업을 복원합니다. 기존 서비스가 삭제되었거나 관리 권한이 없으면 해당 URL을 유지할 수 없을 수 있습니다.
5. QR은 Render 외부 URL을 자동으로 사용합니다. 사용자 도메인을 쓰는 경우 PUBLIC_URL 환경변수로 HTTPS 기본 주소를 설정합니다.

Starter 월 7달러와 1GB 영구 디스크 월 0.25달러를 합하면 **월 7.25달러**입니다. 세금·추가 사용료는 대시보드에서 확인합니다. Render 무료 Web Service에는 영구 디스크가 없고 유휴 시 슬립합니다. SQLite 로컬 파일은 재시작·재배포 시 유실될 수 있습니다. 무료 PostgreSQL은 30일 후 만료되는 대안이지만 사용하려면 앱의 저장 계층을 PostgreSQL로 바꾸고 백업과 동시 갱신을 재검증해야 합니다. 제공된 설정은 SQLite 영구 디스크를 구성합니다. 동일 네트워크의 로컬 운영은 Render 비용 없이 가능합니다. ## 문제 해결

| 증상 | 확인 방법 |
|---|---|
| node 또는 npm.cmd를 찾을 수 없음 | Node.js 24를 설치한 뒤 PowerShell을 새로 엽니다. |
| 패키지를 찾을 수 없음 | 프로젝트 폴더에서 npm.cmd ci를 먼저 실행합니다. |
| QR 접속 실패 | 송출 주소가 localhost라면 스마트폰에서 접근 가능한 LAN IPv4 또는 Render HTTPS 주소로 송출 화면을 다시 엽니다. |
| 파일 형식 오류 | 확장자만 .xlsx로 바뀐 텍스트 파일은 원래 .csv로 되돌리거나 Excel에서 실제 통합 문서로 다시 저장합니다. |
| CSV 한글이 깨짐 | 가져오기 화면에서 CP949/EUC-KR을 지정하거나 원본 XLSX를 올립니다. 결과 CSV는 UTF-8 BOM으로 저장됩니다. |
| 재시작 후 명단이 보이지 않음 | 기존 폴더 또는 DATA_DIR을 확인합니다. Render에서는 디스크 마운트와 DATA_DIR이 같은지 확인합니다. |
| 연결이 잠시 끊김 | 화면에 재연결 안내가 표시됩니다. 같은 브라우저의 쿠키를 유지한 상태에서 기존 시간과 점수를 다시 받습니다. |
| 관리자 로그인 만료 | 12시간이 지났거나 서버가 재시작되면 다시 로그인합니다. |

검증을 다시 실행하려면 npm test를 실행합니다. 테스트는 가상 데이터와 임시 DB로 XLSX·XLS·한글 CSV 가져오기, XLSX 내보내기, 150명 동시 접속, 재시작을 검증합니다. 클라우드와 현장 네트워크의 성능은 실제 운영 환경에서 달라질 수 있습니다.

## 통합 엑셀 한 번에 등록

**관리자 → 백업 및 결과 → 통합 엑셀 일괄 등록**에서 XLSX 파일을 선택하면 바로 저장됩니다. 파일에는 **문제 목록**, 문제 번호로 시작하는 지정 정답 시트, **전체 직원 명단** 시트가 필요합니다. 참가자 등록 전에 사용하세요.

기존 직원은 이름·시설·구분자가 같으면 유지합니다. 제목이 같은 문제는 파일의 문제와 정답으로 갱신됩니다. 다른 제목의 기존 문제는 유지합니다. 문제당 기본 시간은 30초, 정답당 기본 배점은 10점입니다. 형식이나 정답표에 오류가 있으면 저장 전에 중단하며 시트와 행을 표시합니다.
